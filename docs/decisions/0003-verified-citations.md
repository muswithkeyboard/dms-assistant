# ADR 0003. Ссылки проверяет код, вердикт собирают правила

Принято 23.10.2026.

## Контекст

Критерии «проверяемость», «нет ложных обещаний» и «уточняющий вопрос вместо выдумки» проваливаются, если доверять
свободному тексту модели.

## Решение

- Модель возвращает утверждения как JSON: `fragment_id` и дословную `quote`. `citations.verify` ищет цитату
  в тексте фрагмента (нормализация, затем нечёткое совпадение ≥ 92; цитата не короче 25 символов и 4 слов).
  Не найдено — ссылка выбрасывается; положительная проверка без ссылок получает статус `not_found`; утверждение
  без ссылки не показывается.
- Отрицательный факт процитировать нельзя, поэтому у него своё доказательство: статус `absent` ставится, только если
  документ нужного типа для программы загружен и разобран, а совпадения нет; в ответе — ссылка на документ целиком
  и список просмотренного. Иначе `not_found`. `covered=not_found` никогда не даёт «нельзя».
- Противоречия разных уровней решаются по приоритету документов (A3) с предупреждением; для равных уровней —
  метка «недостаточно данных» со статусом «документы противоречат».
- Метку SC 01 («можно / нельзя / при условиях / недостаточно данных») и ветку добавления клиники вычисляют правила `config/verdict_rules.yaml` и `config/branches.yaml`
  из статусов проверок. Модель статусы предлагает, но не выносит вердикт.
- Черновики — шаблоны со слотами; номера пунктов и названия документов подставляет код; фильтр обещаний после
  генерации.

## Последствия

- Ответы суше, чем у «чат-бота», зато каждое слово проверяемо — так и подаём на защите.
- Ошибки извлечения видны в `eval.py` по проверкам, а не размазаны по тексту.
