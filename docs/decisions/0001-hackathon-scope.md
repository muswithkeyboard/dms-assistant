# ADR 0001. Рамки прототипа и работа на допущениях

Принято 23.10.2026, до старта.

## Контекст

Кейс — ИИ-ассистент для менеджеров сопровождения ДМС (`docs/TZ.md`). Ответов организаторов нет: неизвестны
комплект документов, формат эталонов, логика веток, ограничения на LLM, сроки и правила хакатона.

## Решение

1. Строим два сценария кейса до конца, с проверяемыми ссылками, ветками и черновиками. Не строим ничего
   из `docs/plan.md` §1 п. 1.
2. Неизвестное заменяем допущениями A1–A12 (`docs/plan.md` §3). Каждое допущение живёт в одном месте (конфиг или
   схема) и показывается на странице «О прототипе».
3. До комплекта организаторов разрабатываем и меряем на синтетическом комплекте с известной истиной (§9).
   Реальный комплект подключается импортом, без изменения контрактов.
4. Стек и стиль — как в Justmedit (Starlette + Jinja2 + чистый JS, uv, Docker), чтобы переносить проверенные части,
   а не писать заново.

## Последствия

- Риск: допущения A6–A8 могут не совпасть с эталонами. Смягчение: правила в конфиге, `scripts/eval.py` перезапускается за минуты.
- Риск правил о наработках до старта (§1 п. 9): сверить историю git с Положением перед сдачей.
