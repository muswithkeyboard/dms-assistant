# ADR 0012. Разметка таблиц перечня клиник оператором, профиль разметки для СК

Принято 25.10.2026 по запросу пользователя после ADR 0011: договор неизвестной СК подключается только поиском по
пунктам (generic), перечня клиник нет — на вопросы о клиниках «недостаточно данных», выбор клиники (ADR 0010) и
«нет в перечне» недоступны.

## Решение
1. После обработки договора оператор видит таблицы документов договора (docx — таблицы, xlsx — листы):
   `GET /api/clients/contracts/{uNN}/tables` → `TablePreview` (первые строки, размер, подпись заголовка, действующая
   разметка, предложение).
2. Оператор отмечает таблицу как перечень клиник и роли колонок (`TableMapping`: строка заголовка; колонки —
   название клиники (обязательно), юрлицо, адрес, город, вид помощи, программа, франшиза, код, по направлению,
   примечание; постоянные программа / вид помощи для всей таблицы). Пробный разбор показывает первые строки перечня
   и проблемы до сохранения.
3. Сохранение: разметка договора; по флажку — профиль СК (`InsurerProfile`: название СК свободным текстом,
   подпись заголовка, разметка). Подпись — нормализованные ячейки строки заголовка (регистр, пробелы, ё, знаки);
   следующая таблица с той же подписью в любом договоре клиента размечается профилем автоматически при обработке.
4. Обработка (`onboarding.process`) после запасного разбора применяет разметку договора, затем профили по подписи:
   строки перечня — `ClinicRow` с `source_ref` строки таблицы (ссылка проверяется `citations.verify` как строка
   перечня, цитата — ячейка названия), программы из колонки / постоянного значения — в `Contract.programs`.
   Матрицы видов помощи по-прежнему нет: readiness `limited`, но в отчёте — строк перечня N, применённые разметки.
5. Оператор может выбрать «не распознавать формат» (`ClientContract.force_generic`) — договор известной СК
   разбирается запасным адаптером. Это нужно, когда распознавание ошиблось, и даёт ревизию без синтетики: настоящий
   договор комплекта, разобранный как неизвестная СК и размеченный оператором, сравнивается с разбором адаптером.
6. Изоляция (ADR 0005) не меняется: разметка и строки перечня — по договору; профиль хранит только разметку колонок,
   не данные.

## Следствия
- Для неизвестной СК: перечень клиник, кандидаты и выбор клиники, «нет в перечне» после выбора менеджера, поиск по
  перечню. Ответы о покрытии видов помощи без матрицы — по пунктам договора («недостаточно данных» без меток).
- Разметка матрицы «программа × вид помощи» — следующий шаг (тем же механизмом, role = care_matrix).
