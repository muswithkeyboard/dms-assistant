# ADR 0016. Документ в чат: ответ по вложению; добавление в документы договора — по настройке

Принято 28.10.2026 по запросу пользователя: «сделать возможность загрузки документов в чат и получить по нему ответ
сразу конкретно по этому документу, и чтобы человек указывал в настройках — такие документы подгружаются в базу
или нет».

## Решение
1. **Вложение чата.** Кнопка «Прикрепить документ» (и перетаскивание) у поля ввода → `POST /api/chats/{id}/attachments`
   (multipart; проверки как у загрузки документа: `sniff_format`, zipguard, `DMS_MAX_UPLOAD_MB`, имя файла).
   Файл — `data/app/attachments/` (вне репозитория), пункты — разбор запасного адаптера (`adapters/generic.READERS`:
   номера Word из numbering.xml, таблицы строками), карточка и пункты — в AppStore (`chat_attachments`,
   `attachment_clauses`). Вложение принадлежит чату: из другого чата не видно и не открывается (как ADR 0005).
2. **Ответ по вложению.** Пока вложение активно (плашка «По документу: … ✕»), вопрос чата отвечает
   `dms_core/attachment.answer` мимо движка договора: BM25 по пунктам вложения + основы вопроса (без
   вопросительных слов `texts_ru/attachment.yaml`), вопрос «о разделе «X»» — пункты раздела; до 5 пунктов;
   цитата — дословный фрагмент (`guided.fragment`), проверенный `citations.locate_quote` по тексту пункта —
   непроверенная не показывается (`docs/rules.md` п. 1). Меток «можно / нельзя» нет: документ не разобран как договор
   (нет программ, перечня, матрицы). Ответ всегда с оговоркой «условия договора из базы не учитывались».
   После загрузки — сообщение «Документ загружен: N пунктов (разделы …)» и 2–3 кнопки «Что сказано в разделе …»
   по заголовкам документа, без модели. ✕ — вопросы снова по договору; вложение остаётся в «⋯ → Вложения».
3. **Настройка сервиса** (`/settings`, `GET/PUT /api/settings`, AppStore `app_settings`): «Документы, загруженные
   в чат: только в этом чате (по умолчанию) / также добавлять в документы договора». Во втором случае документ
   дописывается к договору чата (в чате ГК — выбранному в диалоге загрузки договору группы) новым методом
   `KitStore.add_documents` (изоляция как в `save`, новая ревизия договора → кэш пунктов и индекс поиска
   пересобираются сами; `onboarding.invalidate`). id — `<договор>.chat_<hex>`, `uploaded_by="chat"`, тип — по
   имени файла или выбор (программа / договор / доп. соглашение / памятка / другое; перечень, правила и каталог —
   «другое»), статус «готов», предупреждение «загружен из чата; повторный импорт удаляет».

## Последствия
- Вложение чата и документ договора — разные вещи: первое не меняет ответы по договору и других чатов; второе
  участвует в обычных ответах по этому договору (и только по нему) наравне с документами комплекта.
- Повторный импорт комплекта и повторная обработка договора клиента (`KitStore.save`) стирают документы, добавленные
  из чата: в карточке вложения остаётся «добавлен в договор», но документа в базе уже нет — загрузить снова.
  Сохранять их через пересборку (как договоры клиентов, ADR 0011) — следующий шаг, если понадобится.
- Пункты вложений хранятся в `app.sqlite` (вне репозитория); в журнал — только id, формат и число пунктов.
- Модель-помощник для вопросов по вложению не используется: поиск по словам документа без модели.
