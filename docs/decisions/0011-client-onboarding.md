# ADR 0011. Подключение клиента: загрузка документов → обработка → договор в поиске

Принято 25.10.2026 по запросу пользователя: новый клиент загружает свои документы, и они сразу обрабатываются и
подключаются к поиску — без участия разработчика и без перезапуска.

## Контекст
- Разбор договора целиком уже есть: адаптеры Зетта / Ренессанс / СОГАЗ и запасной (generic), `KitStore.save` пишет
  или заменяет один договор одной транзакцией. Но вызывается он только общим импортом комплекта (`scripts/ingest_kit.py`),
  который пересобирает базу целиком из `data/raw/`.
- Загрузка файла в интерфейсе (`POST /api/documents`) останавливается на «Полнота проверена»: договор не создаётся,
  в поиск не попадает.

## Решение
1. Клиент создаёт группу компаний и договоры (`ClientGroup`, `ClientContract`: id `ugN` / `uNN`, не пересекаются с
   `gkN` / `cNN` комплекта), загружает файлы. Файлы — вне git: `data/derived/clients/<ugN>/<uNN>/` (общие для группы —
   `data/derived/clients/<ugN>/_group/`), реестр клиентов и заданий — в AppStore (`data/app/app.sqlite`).
2. Обработка — фоновое задание (`OnboardingJob`) по одному договору за раз (сервер 2–4 ГБ; HeavyGate): из файлов
   строится `KitContract` (тип документа — `config/doc_types.yaml` по имени, иначе выбор клиента), затем тот же
   конвейер, что у импорта: определение СК → адаптер → проверка полноты → `KitStore.save` (транзакция по договору) →
   статусы ТЗ п. 7.1 → сброс кэшей договора (перечень для слотов, поиск, индексы) → самопроверка → отчёт
   `OnboardingReport`. Остальные договоры и открытые чаты не затрагиваются.
3. Готовность: `ready` — есть пункты, программы, перечень клиник и матрица видов помощи; `limited` — договор в
   поиске, но без перечня или матрицы (неизвестная СК → generic: ответы по клиникам чаще «недостаточно данных», ложных
   «можно»/«нельзя» не добавляется); `failed` — нет разобранных пунктов. Чат по договору доступен при `ready` и `limited`.
4. Самопроверка: по каждой программе — типовые вопросы о видах помощи матрицы (и о клинике перечня), прогон
   `engine.answer` без модели; в отчёте — сколько ответов с проверенной ссылкой. Это индикатор, не эталон.
5. Повторная обработка (замена или добавление файла) разбирает договор заново и заменяет его в базе. Общий импорт
   комплекта сохраняет договоры клиентов: после пересборки базы он заново разбирает договоры из реестра.
6. Изоляция (ADR 0005): у договора клиента свой contract_id; инструменты, поиск и ответы — как у договоров комплекта.

## Следствия
- Для трёх известных СК подключение даёт ту же систему, что на комплекте; для прочих — поиск по пунктам. Следующий
  шаг — разметка таблиц перечня оператором с сохранением для СК (отдельный ADR).
- Ревизия — без синтетики: договор комплекта загружается заново как клиентский, ответы на наборах ревизий должны
  совпасть с ответами по исходному договору.
- Доступ по ролям и разделение клиентов между собой — вне объёма прототипа (одна организация-пользователь).
