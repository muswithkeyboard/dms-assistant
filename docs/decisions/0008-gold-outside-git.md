# ADR 0008. Эталонные кейсы — вне git, в `data/derived/gold/`

Принято 23.10.2026 автором (волна 1).

## Контекст
План §9 кладёт `gold/k10_k19.jsonl`, `gold/own_*.jsonl`, `gold/holdout.jsonl` в `eval/gold/`. Но эталоны К10–К19 —
документ организаторов, а свои кейсы цитируют пункты договоров комплекта. Правило 4 (`docs/rules.md`): всё производное
от документов организаторов — только `data/raw/`, `data/derived/`, `reference/`.

## Решение
1. Все эталоны — `data/derived/gold/*.jsonl` (вне git). В git — `eval/gold/README.md` со схемой записи
   и `scripts/import_gold.py`, который строит `k10_k19.jsonl` из xlsx организаторов.
2. Свои кейсы пишут агенты-аналитики по документам, не видя кода; файлы `own_gk1.jsonl` … `own_gk3.jsonl`.
   Автор отделяет `holdout.jsonl` (треть, случайно с фиксированным seed, по каждой ГК); при настройке
   промптов holdout не открывается (правило 6).
3. Тесты на эталонах без `data/derived/gold/` — SKIP.

## Последствия
Чистый клон для жюри не содержит эталонов; `docs/test_report.md` (в git) содержит ID кейсов, ожидание и итог
без длинных цитат документов.
