# ADR 0013. Разметка матрицы «программа × вид помощи» оператором (role care_matrix), профиль СК

Принято 26.10.2026 по запросу пользователя после ADR 0012: у неизвестной СК размечается перечень клиник, но матрицы
видов помощи нет — после выбора клиники метка остаётся «недостаточно данных» (care_in_program не устанавливается).

## Решение
Тот же механизм таблиц, что в ADR 0012 (`TableMapping`, пробный разбор, сохранение, профиль СК по подписи, «применить
ко всем таблицам с такой же раскладкой»), три способа:
1. **Широкая таблица** (`role=care_matrix`, `matrix_layout=wide`): колонка видов помощи (`care_type`), колонки
   программ (`program_cols`, по умолчанию — текст заголовка; программа должна совпасть с программой договора или
   перечня — иначе предупреждение).
2. **Длинная таблица** (`matrix_layout=long`): колонки `program`, `care_type`, необязательная `present`; постоянные
   `program` / `program_from_title` — как у перечня.
3. **Из перечня клиник** (`role=clinic_list`, `derive_care=true`): виды помощи строк размеченного перечня дают
   `CareMatrix(present=True)` по программам (так устроены перечни Ренессанса и СОГАЗ).

Значение ячейки: «да / + / входит / включено / ✓ / V» и непустой текст из слов `config/texts_ru/mapping.yaml` →
`present=True`; «нет / — / - / не входит / не включено / x» → `present=False` («нельзя» по матрице — только явное
«нет»); пустая ячейка — строки нет; прочий текст (суммы, лимиты, примечания) — строки нет и предупреждение со
списком (оператор видит, что не учтено). Ссылка строки матрицы — строка таблицы (`source_refs`), проверяется
`citations.verify`. Проверка содержимого (как ADR 0012 п. 1б): колонка видов помощи должна быть похожа на виды
помощи (`config/care_types.yaml` и слова mapping.yaml), колонки программ — на программы договора; иначе
`mapping_suspicious` и подтверждение.

## Следствия
- Неизвестная СК с размеченными перечнем и матрицей — readiness `ready`; «можно» — при выбранной клинике, виде
  помощи в матрице, без исключений и условий (ADR 0010); «нельзя» — исключение пункта или явное «нет» матрицы.
- Ложное «можно» из-за ошибки разметки матрицы возможно только при явном «да» в неверно размеченной колонке; защита —
  проверка содержимого, пробный разбор, ревизия на настоящих договорах с force_generic против адаптеров.
