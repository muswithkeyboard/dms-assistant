# ADR 0002. Модель выбирается сравнением; слой-абстракция

Принято 23.10.2026. Обновлено 23.10.2026: кейсодатель требует сравнение моделей как результат.

## Контекст

Неизвестно, можно ли отправлять тексты договоров во внешние API. Кейсодатель хочет видеть сравнение моделей.

## Решение

- Весь доступ к моделям — через `dms_core/llm/` с интерфейсом `complete_json(prompt_id, variables, schema)`.
- Провайдеры: `anthropic`, `openai_compat` (OpenAI, YandexGPT, vLLM, Ollama — по `base_url`), `gigachat`, `mock`
  (кассеты, без сети). Выбор — `DMS_LLM_PROVIDER`, `DMS_LLM_MODEL`, `DMS_LLM_BASE_URL`, ключи в `.env`.
- Вердикт, ветку и изоляцию договоров обеспечивает код, поэтому замена модели меняет качество извлечения,
  но не логику — сравнение честное.
- `scripts/compare_models.py` → `docs/model_comparison.md` (план §10.1): минимум три модели, включая российскую;
  метрики — точность, сырые выдумки и попытки переноса до фильтра, «не указано» на вопросах без ответа, скорость,
  цена, где обрабатываются данные. Итог — основная и запасная модель.
- Без ключа — `demo_saved` для примеров и `extractive` для прочего.

## Последствия

Промпты пишутся без особенностей одного провайдера: строгий JSON по схеме, примеры в промпте, температура 0.
Нужны ключи нескольких провайдеров (STATUS → «Нужно от пользователя»).
